
1. ลดการซ้ำซ้อนของโค้ด (Single Source of Truth)
    โปรเจกต์นี้มีโมเดลถึง 3 สาย (Tabular, NLP, Vision) และทำงานในหลายส่วนของ ระบบ:
        ถ้าไม่แยก: จะต้องเขียนฟังก์ชันคำนวณ F1-Score หรือ ROC-AUC ซ้ำกันถึง 3-4 ครั้ง ทั้งใน tabular_model.py, nlp_model.py, vision_model.py หรือแม้แต่ในไฟล์ Unit Test
        ถ้าแยก: เขียนสูตรคำนวณและตั้งค่ามาตรฐานไว้ที่ metrics.py ที่เดียว ถ้าอนาคตต้องการปรับ Logic (เช่น ปรับค่า zero_division=0 หรือเปลี่ยนวิธีเฉลี่ย F1-Score) ก็แก้ที่ไฟล์นี้ที่เดียว ทุกโมเดลในระบบจะอัปเดตตามทันที

2. หลักการ Separation of Concerns (แยกหน้าที่ชัดเจน)
    ในสถาปัตยกรรมซอฟต์แวร์ที่ดี แต่ละไฟล์ควรมีหน้าที่เดียว (Single Responsibility Principle):
        models/*.py: มีหน้าที่จัดการ Model Lifecycle เท่านั้น (กำหนดสถาปัตยกรรม, เทรน, โหลด weight, ทำ Inference)
        utils/metrics.py: มีหน้าที่ ประเมินผล (Evaluate) และแปลงตัวเลขทางสถิติให้พร้อมใช้งาน
        ถ้าเอาทุกอย่างไปรวมในไฟล์โมเดล ไฟล์นั้นจะบวม (God File) อ่านยาก Debug ยาก และแก้ไขโครงสร้างโมเดลลำบาก

3. เรียกใช้งานได้ในหลาย Layer ของระบบ (Reusability)
    ฟังก์ชันวัดผลไม่ได้ถูกใช้แค่ตอน "เทรนโมเดล" เท่านั้น แต่มันถูกเรียกใช้ในหลายๆ จุดของ Lifecycle:
        ช่วง Training: เรียกใช้เพื่อวัดผล Validation Set ในแต่ละ Epoch
        ช่วง Evaluation / Testing: ไฟล์ tests/test_api.py เรียกใช้เพื่อตรวจสอบความแม่นยำของระบบก่อน Deploy
        ช่วง Monitoring (อนาคต): ฝั่ง FastAPI Backend อาจดึงฟังก์ชันนี้ไปคำนวณ Performance ของโมเดลบน Production เพื่อดูว่าโมเดลเริ่มแม่นยำลดลง (Model Drift) แล้วหรือยัง

4. ทำให้ Unit Testing ทำได้ง่ายขึ้น (Testability)
    การแยกฟังก์ชันคำนวณออกมาเป็น Pure Function (ใส่ Input A ได้ Output B เสมอ โดยไม่ขึ้นกับสภาพแวดล้อมของโมเดล) ทำให้เราสามารถเขียน Unit Test เพื่อทดสอบสูตรคำนวณ metric ได้ง่ายๆ โดยไม่ต้องเสียเวลาโหลดโมเดล PyTorch หรือ XGBoost ตัวหนักๆ ขึ้นมาจำลอง

สรุปเปรียบเทียบง่ายๆ:
    models/ เหมือน "เครื่องจักร/คนทำอาหาร" มีหน้าที่แปรรูปวัตถุดิบ
    metrics.py เหมือน "ตลับเมตร/ตาชั่ง" มีหน้าที่วัดขนาดและมาตรฐาน
    เราจึงแยกตลับเมตรไว้ในกล่องเครื่องมือ (utils/) เพื่อให้ช่างทุกคนหยิบไปวัดผลงานตัวเองได้ โดยไม่ต้องสร้างตลับเมตรใหม่ขึ้นมาเองในทุกๆห้อง
